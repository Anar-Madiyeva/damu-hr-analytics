# PRD — Сайт HR-аналитики АО «Фонд «Даму»

**Версия:** 1.0
**Дата:** 07.11.2026
**Статус:** Утверждён к разработке (макет реализован)
**Владелец продукта:** Департамент по работе с персоналом
**Заказчик:** Руководство АО «Фонд «Даму»

---

## 1. Общее описание

Веб-страница (одностраничный аналитический отчёт) для предоставления Руководству Фонда количественного и качественного анализа персонала в виде диаграмм, таблиц и текстовых выводов. Отчёт формируется на основе данных, загружаемых Департаментом по работе с персоналом, и используется Руководством как рабочий инструмент при принятии кадровых решений.

## 2. Проблема и обоснование

Кадровая отчётность Фонда ведётся в разрозненных Excel-файлах (численность, движение, обучение, резерв, мотивация). Руководству требуется единый визуализированный отчёт, который:

- консолидирует все HR-показатели в одном месте;
- даёт представление о динамике (сравнение периодов);
- содержит готовые выводы и рекомендации, а не только «сырые» цифры;
- выглядит презентабельно для демонстрации на уровне Правления.

## 3. Цели и метрики успеха

| Цель | Метрика успеха |
|---|---|
| Единый отчёт вместо разрозненных файлов | 100% ключевых HR-показателей представлены на одной странице |
| Сокращение времени подготовки отчёта | Обновление данных — не более 30 минут (редактирование одного файла) |
| Использование в работе Руководства | Отчёт используется на ежеквартальных кадровых совещаниях |
| Актуальность данных | Отчёт обновляется не реже 1 раза в квартал |

## 4. Целевая аудитория

- **Первичная:** Председатель Правления, управляющие директора (потребители отчёта).
- **Вторичная:** Департамент по работе с персоналом (администратор данных, автор выводов), руководители департаментов (анализ загруженности своих подразделений).

## 5. Объём продукта (Scope)

### Входит в объём

1. Одностраничный HTML-отчёт (открывается в браузере, не требует сервера).
2. Семь аналитических разделов (см. п. 7).
3. Интерактивные диаграммы (Chart.js) и таблицы.
4. Текстовые выводы и рекомендации по каждому направлению.
5. Демонстрационные данные для презентации макета (текущая версия).
6. Механизм обновления данных через редактирование единого файла `data.js`.

### Не входит в объём (Out of Scope)

- Авторизация и разграничение доступа (отчёт — внутренний документ).
- Автоматическая интеграция с 1С/HRM-системами (на этапе 1).
- Экспорт в PDF/PowerPoint (печать из браузера покрывает потребность).
- Мобильное приложение.
- Хранение истории отчётов (решается сохранением версий файлов).

## 6. Нефункциональные требования

| Категория | Требование |
|---|---|
| Совместимость | Chrome, Edge, Firefox — актуальные версии; корректное отображение от 1280px |
| Производительность | Загрузка страницы ≤ 3 сек при корпоративном интернете |
| Доступность файла | Самодостаточный набор из 4 файлов (`index.html`, `styles.css`, `app.js`, `data.js`), работает с сетевого диска |
| Зависимости | Единственная внешняя зависимость — CDN Chart.js (при недоступности интернета диаграммы не рендерятся; резерв — локальная копия библиотеки) |
| Печать | Корректная печать/сохранение в PDF через браузер (Ctrl+P) |
| Конфиденциальность | Данные — для служебного пользования; маркировка в футере страницы |
| Поддерживаемость | Все данные отделены от кода (файл `data.js`); обновление не требует навыков программирования |

## 7. Функциональные требования

### FR-1. Раздел «Ключевые показатели»
KPI-карточки: списочная и фактическая численность, принято, уволено, коэффициент текучести, вакантные ставки, сотрудники в декретном отпуске. Каждая карточка показывает значение за период и динамику к предыдущему периоду (▲/▼ с цветовой индикацией; для текучести и вакансий — инвертированная логика «рост = плохо»).

### FR-2. Раздел «Структура персонала»
- Численность по подразделениям (план/факт, ТОП-15, горизонтальная диаграмма).
- Возрастная структура (4 группы, сравнение двух периодов).
- Гендерная структура (все сотрудники и отдельно — руководящие должности).
- Категории персонала (высшее звено / среднее звено / специалисты / рабочие).
- Образовательный уровень, стаж работы, социальный портрет (многодетные, одинокие родители, родители детей-инвалидов).

### FR-3. Раздел «Движение персонала»
- Приём/увольнения в динамике периодов.
- Источники привлечения кандидатов (HeadHunter, LinkedIn, внутренний конкурс, реферальная программа, резерв, агентства).
- Причины увольнений, ТОП-7 подразделений по текучести, текучесть по возрастным группам.

### FR-4. Раздел «Загруженность подразделений»
- Индекс загруженности каждого подразделения (0–100) с цветовой индикацией статуса: Критическая (≥95), Высокая (85–94), Оптимальная (70–84), Умеренная (<70).
- Детализация в таблице: количество задач, штат, часов на задачу, индекс, статус.
- **Методология индекса** определяется HR совместно с руководителями подразделений и документируется отдельно (в текущей версии — экспертная оценка на основе задач/часов).

### FR-5. Раздел «Обучение и развитие»
- Количество обученных за отчётный период (всего, внешнее/внутреннее, доля от численности).
- Разрезы: по категориям персонала, по направлениям обучения.

### FR-6. Раздел «Качественные показатели»
- Результаты оценки деятельности (высокая/средняя/низкая эффективность, динамика).
- Кадровый резерв: состав, доля прошедших подготовку, назначенные из резерва.
- Назначения: внутренние/внешние, по уровням должностей.
- Награждения: количество, виды поощрений.
- Изменение должностных окладов: количество сотрудников, средний процент повышения.

### FR-7. Раздел «Выводы и рекомендации»
Текстовые аналитические заключения по 6 направлениям (численность, качественный состав, загруженность, обучение, резерв, мотивация). Тексты пишет ДРП на основе актуальных данных; место размещения фиксировано в шаблоне.

### FR-8. Навигация
Липкая верхняя навигация с якорями по разделам и подсветкой активного раздела при прокрутке.

## 8. Требования к данным

- Источник данных — единый файл `data.js` (формат JavaScript-объектов), редактируемый вручную.
- Периодичность обновления: ежеквартально (минимум), рекомендуется ежемесячно.
- Все показатели хранятся с разбивкой на два сравниваемых периода (текущий и предыдущий).
- Ответственный за актуальность: назначенный специалист ДРП.
- Требование к качеству: перед публикацией данные сверяются с первичными учётными системами (штатное расписание, приказы, учёт обучения).

## 9. Дизайн

- Деловой стиль: светлый фон, корпоративный синий (#0b5fa5), сдержанная палитра.
- Читаемая типографика (Segoe UI / системные шрифты), размер шрифта не менее 12px на диаграммах.
- Цветовая семантика: зелёный — позитив, янтарный — внимание, красный — критическое отклонение.
- Адаптивность: сетки 3/2 колонок сворачиваются на узких экранах.

## 10. План работ (Roadmap)

| Этап | Содержание | Статус |
|---|---|---|
| 1. Макет | Одностраничный отчёт на демо-данных, все 7 разделов | ✅ Готово (07.11.2026) |
| 2. Загрузка реальных данных | ДРП передаёт фактические показатели; обновление `data.js` | Ожидает данных |
| 3. Валидация | Сверка с учётными системами, согласование с ДРП | Не начат |
| 4. Пилот | Представление Руководству, сбор обратной связи | Не начат |
| 5. Развитие (опционально) | Загрузка Excel прямо на странице, локальная копия Chart.js, сравнение >2 периодов, экспорт в PDF | По итогам пилота |

## 11. Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| Данные в разных файлах имеют разную методику подсчёта | Высокая | Зафиксировать методологию по каждому показателю до этапа 2 |
| CDN Chart.js недоступен в закрытом контуре | Средняя | Добавить локальную копию библиотеки в комплект поставки |
| Ошибки при ручном обновлении `data.js` | Средняя | Чек-лист проверки + контрольные суммы (итоги по разделам); на этапе 5 — переход на загрузку Excel |
| Утечка конфиденциальных данных | Низкая | Файл не публикуется во внешних средах; распространение только по внутренней почте/диску |

## 12. Критерии приёмки

1. Отчёт открывается двойным кликом по `index.html` без установки ПО и отображается без ошибок.
2. Все 7 разделов содержат актуальные данные; отсутствуют демо-значения.
3. Итоговые суммы по разделам сходятся с первичными учётными данными (±0).
4. Выводы и рекомендации актуальны и подписаны ответственным ДРП.
5. Отчёт корректно печатается в PDF из браузера.
6. Руководство подтверждает пригодность отчёта для кадровых совещаний.

## 13. Открытые вопросы

1. Периодичность обновления: ежемесячно или ежеквартально?
2. Нужна ли детализация по филиалам в разделе загруженности (сейчас — центральный аппарат)?
3. Утвердить методологию индекса загруженности (задачи, часы, нормативы).
4. Требуется ли версия отчёта на казахском языке?
5. Кто утверждается ответственным за публикацию обновлений?
